# 09. Just

> **Project:** [casey/just](https://github.com/casey/just) · CC0 (public domain) · single Rust binary
> **Used in:** [sharifndlovu123/speedward](https://github.com/sharifndlovu123/speedward), whose `justfile` wraps lint, tests, the dev server and the Docker stack (see [[17. Web Performance from Around the World|Web Performance from Around the World]]).

**just** is a **command runner**. You write the commands a project needs (`test`, `lint`, `serve`, `up`) in a file called `justfile`, and `just <name>` runs them. It looks like `make`, but it is only a runner: it does not track files or decide what is out of date, so none of `make`'s quirks (tabs, `.PHONY`, implicit rules) apply.

Why bother: the commands people really type (`.venv/bin/pytest -q`, `docker compose up -d --build`) live in one self-documenting list instead of in the README, shell history or CI YAML, and a newcomer runs `just` to see them all.

## Just vs make vs shell scripts

| | `just` | `make` | `scripts/*.sh` |
| --- | --- | --- | --- |
| Purpose | Run named tasks | Build files from sources | One-off scripts |
| File-change tracking | No | Yes (its main job) | No |
| `.PHONY` needed | No | Yes for task targets | n/a |
| Arguments | Real parameters with defaults | Awkward (`make x ARG=1`) | `$1`, `$@` |
| Lists tasks | `just --list` | Not built in | `ls` |
| Loads `.env` | `set dotenv-load` | Manual | Manual |
| Runs from any subfolder | Yes, finds the `justfile` upward | Only with `-C` | Manual |

Use `make` when you build files and want incremental rebuilds (C, some static site builds). Use `just` for "run the tests / start the stack" tasks.

# Install

```
$ sudo apt install just          # Debian, Ubuntu
$ brew install just              # macOS, Linux
$ cargo install just             # any platform with Rust
$ pip install rust-just          # from PyPI, so it can live in a project's virtualenv
```

`pip install rust-just` is how Speedward ships it: the `dev` extra in `pyproject.toml` lists `rust-just`, so `pip install -e ".[dev]"` puts `just` in the venv (run it as `.venv/bin/just`). Check with `just --version`.

# A first justfile

Recipes are a name, a colon, then **indented** commands. A comment on the line above a recipe becomes its description in the list.

```just
# justfile
name := "world"

# Say hello
hello who=name:
    echo "hello {{who}}"

# Run the tests, passing any extra arguments through
test *args:
    pytest -q {{args}}

# Lint and test
check: lint test

lint:
    ruff check .
```

```
$ just --list
Available recipes:
    check
    hello who=name # Say hello
    lint
    test *args     # Run the tests, passing any extra arguments through

$ just hello Sharif
echo "hello Sharif"
hello Sharif

$ just test tests/test_runner.py -v      # extra args go to pytest
$ just check                             # runs lint, then test
```

Running `just` with no recipe name runs the **first recipe** in the file, so a common pattern is a `default` recipe that lists everything.

## The pieces

| Piece | Syntax | Meaning |
| --- | --- | --- |
| Variable | `venv := ".venv/bin"` | Used as `{{venv}}/pytest` |
| Backtick variable | `year := ` then a command in backticks | Value is the command's output (e.g. `date +%Y`) |
| Parameter | `serve port="8000":` | Default value makes it optional |
| Variadic | `test *args:` or `test +args:` | `*` is zero or more, `+` is one or more |
| Dependency | `check: lint test` | Run these first, each at most once per invocation |
| Dependency with arguments | `check: (test "-x")` | Parentheses pass arguments |
| Quiet line | `@echo hi` | Do not echo the command before running it |
| Quiet recipe | `@build:` | Applies `@` to every line |
| Comment | `# text` | The line above a recipe is its doc |
| Function | `{{just_executable()}}` | Built-ins such as `os()`, `env("HOME")`, `justfile_directory()` |

Run a recipe in another language by starting it with a **shebang** line; the whole recipe is written to a temporary file and run as one script:

```just
stats:
    #!/usr/bin/env python3
    import platform
    print(platform.python_version())
```

# Behaviours worth knowing

- **Each line runs in its own shell.** `cd build` on one line does not affect the next. Put related commands in a shebang recipe, or join them on one line with `&&`.
- **It runs from the justfile's folder**, even if you type `just` in a subfolder, so relative paths are stable. Just searches parent directories for the `justfile`.
- **A failing line stops the recipe** and `just` exits non-zero, so CI treats it as a failure. Put `-` before a line to ignore its failure.
- **Settings** go at the top: `set dotenv-load` loads a `.env` file into the environment, `set positional-arguments` passes arguments as `$1`, `$2`, `set shell := [...]` picks the shell.
- **Attributes** go on the line above a recipe: `[private]` hides it from `--list`, `[confirm]` or `[confirm("Really deploy?")]` asks yes/no first, `[group("docker")]` groups the list, `[doc("text")]` sets the description.
- **Imports and modules** (`import "ci.just"`, `mod docker`) split a big file into pieces.

## Command line

```
$ just                     # first recipe (often a list of tasks)
$ just --list              # all public recipes with their comments
$ just --list --unsorted   # in file order instead of alphabetical
$ just --summary           # recipe names on one line
$ just --choose            # pick a recipe interactively (needs fzf)
$ just --show test         # print one recipe's source
$ just --dry-run check     # print what would run, do not run it
$ just --evaluate          # print the values of all variables
$ just -f other.just       # use a different file
$ just --fmt --unstable    # rewrite the justfile in canonical formatting
```

# Worked Example: Speedward's justfile

The Speedward repo keeps its everyday commands in one file. The README says they "only wrap the commands below", so you can still run those directly; `just` is the shortcut, not a requirement.

```just
venv := ".venv/bin"

# List the tasks
default:
    @{{just_executable()}} --list --unsorted

# Lint (never run `ruff format`: the code is not auto-formatted)
lint:
    {{venv}}/ruff check .

# Unit tests (pass extra pytest args, e.g. `just test tests/test_runner.py -v`)
test *args:
    {{venv}}/pytest -q {{args}}

# Lint and unit tests, the same as CI's fast jobs
check: lint test

# Estimate the test cost of a scan without spending any tests
estimate url:
    {{venv}}/speedward scan {{url}} --estimate

# Start the Docker stack: speedward plus the location-file updater
up:
    docker compose up -d --build
```

What it shows:

- **`default` lists the tasks.** Typing just `just` prints the menu. `just_executable()` is the path of the running binary, so it works however `just` was installed.
- **A variable for the venv path** means every recipe calls the project's own tools (`.venv/bin/pytest`) without activating the environment.
- **`test *args`** forwards flags, so `just test tests/test_runner.py -v` works with no new recipe.
- **`check: lint test`** is a dependency recipe that mirrors CI's fast jobs, so "does it pass locally?" and "does it pass in CI?" are the same question.
- **A required parameter** (`estimate url`) fails with a clear message if you forget the URL.
- Comments double as help text, so the `--list` output is the documentation of the workflow.

## In CI

CI can call the same recipes, so the pipeline and a laptop run identical commands. GitHub Actions has no `just` preinstalled; install it in a step (for example `sudo apt install just` on an Ubuntu runner, or the project's setup action) and then run `just check`. Pipeline concepts are in [[1. CI-CD Pipelines|CI-CD Pipelines]] and [[2. GitHub Actions|GitHub Actions]].

# Good practice

- Keep recipes **thin**. If a recipe grows past a few lines, move the logic into a script (`scripts/update_geoip.sh`) and have the recipe call it.
- Make `default` print the list so the file doubles as onboarding.
- Comment every public recipe; mark helpers `[private]`.
- Do not hide secrets in a `justfile`; use `.env` with `set dotenv-load`, kept out of Git.
- Mention the install command in the README so nobody is surprised by a missing `just`.
