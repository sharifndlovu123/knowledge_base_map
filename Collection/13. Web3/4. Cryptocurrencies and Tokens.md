# 04. Cryptocurrencies and Tokens

Coins versus tokens, how fees work, stablecoins, DeFi building blocks and layer 2 networks.

> **Not from the library.** General reference material, not investment advice. Prices, fees and protocol parameters change; check official sources.

## At a glance

| Concept | In one line | Use it when |
|---|---|---|
| Coin | Native asset of a chain, pays fees | Bitcoin (BTC), Ether (ETH) |
| Token | Asset defined by a smart contract | USDC, governance tokens, NFTs |
| Gas | Fee for computation and storage | Estimating the cost of a transaction |
| Stablecoin | Token pegged to another asset | Moving value without price swings |
| DEX / AMM | Swap via a liquidity pool | Trading without a central exchange |
| Layer 2 | Chain that settles to another chain | Cheaper, faster transactions |

## Bitcoin and Ether

| | Bitcoin | Ethereum |
|---|---|---|
| Purpose | Scarce digital money | Programmable platform plus money |
| Supply | Capped at 21 million | No hard cap; issuance and burning are protocol rules |
| Model | UTXO | Account |
| Contracts | Limited scripting | General-purpose (EVM) |
| Consensus | Proof of Work | Proof of Stake |

## Gas (Ethereum model)

- Every operation costs **gas** units; a simple transfer is 21,000 gas. Storing data costs far more than arithmetic.
- Fee = gas used x gas price, paid in the native coin. Since EIP-1559 the price is a protocol **base fee** (burned) plus an optional **priority tip** to the block producer.
- A transaction that runs out of gas fails but still pays for the work done. Wallets set a **gas limit** as an upper bound.
- Unit: 1 ETH = 10^18 wei. Smart contracts and APIs use integers in the smallest unit, never decimals.

## Token standards

| Standard | What it is | Notes |
|---|---|---|
| ERC-20 | Fungible token | `balanceOf`, `transfer`, `approve`, `transferFrom`; `decimals` is optional in the spec |
| ERC-721 | Non-fungible token (NFT) | Each token id is unique and has an owner |
| ERC-1155 | Multi-token | Fungible and non-fungible ids in one contract |
| ERC-4626 | Tokenised vault | Standard interface for yield-bearing deposits |

- A token's balances live in the **token contract's storage**, not in your wallet. The wallet only holds the key that may update that entry.
- **Approvals**: `approve(spender, amount)` lets another contract pull tokens later. Unlimited approvals are a common way people get drained.
- **Decimals**: ERC-20 amounts are integers scaled by the token's `decimals` (USDC uses 6, many others 18). Mixing them up is a classic bug.

## Stablecoins

| Type | Backing | Main risk |
|---|---|---|
| Fiat-backed | Reserves held by an issuer | Issuer solvency, freezing, regulation |
| Crypto-collateralised | Over-collateralised on-chain assets | Collateral crash, liquidation, oracle failure |
| Algorithmic | Incentives and a paired token | Death spirals; several have collapsed |

## DeFi building blocks

- **AMM** (automated market maker): a pool holds two tokens and a formula sets the price. The classic rule is `x * y = k`, so buying one token makes it dearer. Liquidity providers earn fees but face **impermanent loss** when prices diverge.
- **Lending**: deposit collateral, borrow against it, and be **liquidated** if collateral value falls below a threshold.
- **Oracles**: contracts cannot see the outside world, so price feeds are supplied by oracle networks. Weak oracles are a leading attack path.
- **Composability**: protocols call each other freely ("money legos"). It speeds building and also spreads failures.

## Layer 2 and bridges

- **Rollups** run transactions off the main chain and post compressed data and proofs back, inheriting its security. Optimistic rollups assume validity and allow a challenge period; zero-knowledge rollups post validity proofs.
- **Bridges** move assets between chains by locking on one side and minting on the other. They hold large pooled funds and have been repeatedly exploited; treat bridged assets as carrying the bridge's risk.

## Common mistakes

- Confusing a token's contract address across chains; the same symbol on another chain is a different contract.
- Ignoring slippage and fees on small swaps.
- Chasing high yields without asking where the yield comes from.

## Recall

1. What is the difference between a coin and a token?
2. Why is an unlimited ERC-20 approval risky?
3. What does `x * y = k` imply when you buy a lot of one token?
4. Who bears the risk when you use a bridge?

??? note "Answers"
    1. A coin is a chain's native asset; a token is a balance table kept inside a smart contract.
    2. The approved contract can pull all your tokens at any time, so a bug or compromise there drains you.
    3. The price moves sharply against you as the pool's supply of that token shrinks (slippage).
    4. You do, in addition to the destination chain's risk, because the bridge holds the locked assets.
